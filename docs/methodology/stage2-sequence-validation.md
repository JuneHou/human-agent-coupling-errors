# Validating the Stage-2 coding sequence against published open-coding method

Checks the order in which Stage-2 components are labelled, and which component licenses which, against the methodological literature. Every quotation below was extracted from the source PDF and matched verbatim; nothing is cited from memory. Unverified items are listed at the end rather than smoothed over.

---

## Conclusion

**The sequence is valid, and stronger than "defensible" — it reproduces the published order of a hybrid deductive–inductive design step for step** (Fereday & Muir-Cochrane, 2006). No step is out of order, none is missing, and the two places where we depart from the literature are both places where we are stricter: the reliability test is a full stage rather than a check, and codes must state their discriminator in computable terms rather than in prose.

**The support relations run in one direction each, and that is what makes the taxonomy falsifiable.** Theory flows *down* as far as the frame and stops; data flows *up* from occurrences and forms every type; the two meet at the event statement and nowhere else.

| | supports | does **not** support |
|---|---|---|
| STPA | the hazard set, the five-part statement form, the four unsafe types | any error type |
| Signal placements | admission of an occurrence as evidenced | what the occurrence means |
| The event | which hazard was created or maintained | itself — it is admitted only on placements |
| The occurrence | the open code naming its mechanism | the frame, which is not revised against it |
| Open codes | error types, by constant comparison | the hazard set |

The frame is never revised against what the corpus turns out to contain. That is the whole falsifiability claim: a coupling failure that fits no hazard is reported uncovered rather than absorbed, so "this is a coupling error" can come out false.

**Three risks survive validation and cannot be designed away.**

1. **Confirmation is intrinsic to directed coding** — Hsieh & Shannon and Fereday state it independently. Blinding and residual reporting reduce it; nothing eliminates it. It must be declared as a limitation, not answered.
2. **The purpose is descriptive, so the empirical iteration carries the weight.** Compliant, but only because type formation is empirical; if the frame ever starts generating types, the design fails Nickerson's own guidance.
3. **One agreement round means the post-refinement number is in-sample** — a pre-existing issue, unchanged by this check.

**Two citations are unverified and one requirement was unsourced until now** — details in §4 below.

## 1. The sequence is Fereday & Muir-Cochrane's six stages, one for one

Fereday & Muir-Cochrane (2006), *IJQM* 5(1):80–92, is already our cited licence for mixing theory-supplied and data-supplied fields. Their six stages are stronger than that: they fix an *order*, and ours reproduces it.

| Their stage (verbatim heading) | Our step | Same thing? |
|---|---|---|
| 1. Developing the code manual — "the template was developed **a priori**, based on the research questions and theoretical concepts" | Hazards H1–H3 and the control-action list declared before coding (§3.3.2, §3.3.5) | yes |
| 2. Testing the reliability of the code — "determine the applicability of the code to the raw information… I invited my supervisor to code the documents as well" | The Stage-1 agreement round: three annotators, same conversations, rubric revised on disagreement (§3.2.4) | yes |
| 3. Summarizing data and identifying initial themes — "reading, listening to, and summarizing the raw data" | Reconstructing the event from the paired turn, observable only (§3.3.5) | yes |
| 4. Applying template of codes **and additional coding** | Assigning the hazard link (template) and writing the open code for the mechanism (additional) — done in one pass (§3.3.6) | yes |
| 5. Connecting the codes and identifying themes | Constant comparison, clustering open codes into error types (§3.3.6, §3.3.7) | yes |
| 6. Corroborating and legitimating coded themes | Held-out validation by a coder outside the derivation (§3.3.7) | yes |

**This settles the order question.** The a-priori template comes first and the per-occurrence application comes at stage 4 — after the data has been summarized at stage 3. So the hazard *set* precedes coding and the hazard *assignment* follows the event, which is exactly what §3.3.5 now states. Fereday's own diagram of the stages is "presented as a linear, step-by-step procedure… for the purposes of written clarity" while being "an iterative and reflective process," which is also how we run stages 4–5.

Their code format is Boyatzis's (1998): a code is "1. the code label or name, 2. the definition of what the theme concerns, and 3. **a description of how to know when the theme occurs.**" That third element is precisely our requirement that every code state its discriminator in computable terms — currently asserted in §3.3.6 with no source. **Cite Boyatzis.**

## 2. Which component supports which

| Support relation | Direction | Licensed by |
|---|---|---|
| Theory → the a-priori frame (hazards, statement form) | theory supplies, data does not revise | Hsieh & Shannon (2005) directed content analysis: "the first step is to identify important key concepts or variables as initial coding categories"; Fereday stage 1 |
| Signal placements → admissibility of an event | evidence gates the event, not the reverse | ours (witnessed-only rule); no external precedent needed — it is a restriction, not a licence |
| Event → hazard assignment | event first, hazard second, per occurrence | Fereday stage 4 (template applied to summarized data, stage 3 → 4) |
| Event → open code | the mechanism is abstracted from the occurrence | Hsieh & Shannon: predetermined codes "then allow additional codes to emerge"; Fereday stage 4 "additional coding" |
| Open codes → error type | many-to-one, by constant comparison | Boeije (2002), *Quality & Quantity* 36:391–409 |
| Error types → taxonomy | terminated by ending conditions, not by exhaustion of data | Nickerson, Varshney & Muntermann (2013), *EJIS* 22(3):336–359 |

**Constant comparison runs inside-out, and ours does too.** Boeije's step 1 is "Comparison within a single interview… every passage of the interview is studied to determine what exactly has been said and to label each passage with an adequate code," whose aim "is to develop categories and to label them with the most appropriate codes"; only then does comparison move between cases and between groups. Our within-conversation comparison (does a later block correct the divergence? does an `analysis` return contradict the `ai` block?) precedes across-conversation clustering for the same reason.

## 3. Where the literature pushes back — three findings that change the paper

**(a) The named weakness of directed content analysis is our exact design, and we cite the method only approvingly.** Hsieh & Shannon state it plainly: **"Researchers are more likely to find evidence that is supportive of the theory."** Fereday's stage 6 says the same thing independently — "Fabricating evidence can be a common problem in the process of interpreting data… the unintentional, unconscious 'seeing' of data that researchers expect to find." We have two mitigations already (coders blind to the directional prediction; residual reported rather than eliminated), but §3.3 never names the risk they mitigate. Citing a method's licence while omitting its stated limitation is the kind of thing a methods-literate reviewer catches. **Fix: state the limitation and pair it with the mitigations.**

**(b) Nickerson's method requires both iteration directions, and prioritizes the empirical one for taxonomies like ours.** Kundisch, Muntermann, Oberländer, Rau, Röglinger, Schoormann & Szopinski (2022), *BISE* — Muntermann is a Nickerson co-author — codify the guidance: "Start with a conceptual-to-empirical iteration if the existing knowledge base holds relevant insights… start with an empirical-to-conceptual iteration if a significant number of objects are available"; "**Conduct at least one empirical-to-conceptual iteration and at least one conceptual-to-empirical iteration**"; and "prioritize conceptual-to-empirical approaches if the taxonomy purpose is normative (i.e., what should be); prioritize **empirical-to-conceptual approaches if the taxonomy purpose is descriptive (i.e., what is)**."

Our purpose is descriptive — which coupling errors actually occur — so the weight belongs on the empirical side. Our design does put it there: theory supplies the hazard frame and the statement form, while every error type is abstracted from coded occurrences. But §3.3 leads with the theory and never says this, so it currently reads as if the frame were doing the type-forming work. **Fix: state the purpose as descriptive and say which iteration direction forms the types.**

**(c) Our two-stage split occupies Fereday's stage 2.** Their reliability test is a step *inside* one analysis, run before the template is applied. Ours is a whole stage with three annotators and per-signal $\kappa$. That is a strengthening, not a departure, and is worth one sentence in §3 as a defence of the two-stage design against "why not code failures directly."

The EJIS PDF is paywalled from here; the secondary source (Kundisch et al. 2022) has only "all the following characteristics and dimensions of the taxonomy **must relate to** this meta-characteristic."
